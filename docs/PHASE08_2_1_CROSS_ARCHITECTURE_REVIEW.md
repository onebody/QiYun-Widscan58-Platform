# Phase 08.2.1 — 跨架构审查

> 项目：QiYun / widscan58
> 阶段：Phase 08.2.1 — 实际代码审计结果补充约束
> 状态：**PROPOSED（待人工审批）**
> 日期：2026-11-05
> 约束：本轮不修改业务代码、数据库、API、协议

## 1. 审查范围与结论

本审查把多站点、事件流、权限三条主线放在同一张图上交叉验证，回答“能否只做 UI/能否并行/先做哪个”。

**总体结论：**

1. 三条主线**不能并行落地**；存在硬依赖：**安全 → 多站点后端 → 前端多站点/写 UI**。
2. 事件流（Agent 上行）与前端事件流属于**独立后端能力**，不得塞进 UI 集成。
3. 当前 UI 可继续做**只读视觉/交互设计**（08.3），但不得设计写操作、角色、切换器、实时推送。
4. `/platform/` 与 `/app/` 的独立部署边界**建议冻结**。
5. 所有决策保持 **PROPOSED**。

## 3. 交叉依赖分析

### 3.1 安全 × 多站点

```text
多站点（可见范围扩大）
    │
    ├── 若无 AuthN/AuthZ：任何访问者可见全部 Site → 跨 Site 泄漏（高）
    ├── 若无 Site Scope：客户端传 site_id 即可越权
    └── 若先做 UI 切换器：等于给越权提供入口

结论：安全（08.2.2）必须先于多站点后端；多站点后端必须先于 UI 切换器。
```

### 3.2 安全 × 事件流

```text
前端 WS（/ws/v1/site）
    │
    ├── 订阅必须认证（否则匿名可订阅全量）
    ├── 必须 Site Scope（否则跨 Site 推送）
    ├── 慢客户端/重连需要游标与快照
    └── 不得在 WS 中传高频 RAWIQ

结论：前端 WS 不是“前端功能”，而是“认证 + 授权 + 订阅管理”的后端能力。
```

### 3.3 事件流 × 多站点

- 未来订阅主题必须按 `site_id` 分区；`event_id` 幂等键已按 `(site_id,event_id)` 设计，天然支持。
- Agent 上行事件不含 `site_id`；由凭证绑定的 Agent 归属推导，多站点时必须保证 Agent 不跨 Site 改绑。

### 3.4 UI × 事件流

| 组合 | 是否允许 |
|---|---|
| 现在设计“实时刷新动画/推送状态” | 否：无推送能力，会出现假交互 |
| 现在设计“轮询中/已刷新/连接状态” | 是：已有真实实现 |
| 现在设计“订阅管理/慢客户端提示” | 否：能力不存在 |
| 未来同时支持“推送 + 轮询降级” | 是（后端就绪后） |

### 3.5 UI × 安全

| 组合 | 是否允许 |
|---|---|
| 只读页面视觉设计 | 是 |
| 登录态/用户菜单/角色徽标 | 否（无认证；08.3 仅可做“未登录”态占位规范，需审批） |
| 无权限/禁止访问态 | 否（无授权模型） |
| 写操作按钮（认领/删除/改配置） | **禁止** |
| “隐藏按钮实现权限” | **禁止** |

### 3.6 Console × 平台

| 项 | 结论 |
|---|---|
| 是否共享 Site 上下文 | 否 |
| 是否共享设备连接 | 否 |
| 是否注入平台 token | 否 |
| 是否随多站点改造 | 否（冻结） |
| 是否允许 iframe 内嵌 | 否（已裁定独立入口） |

## 4. 冲突与裁定

| 冲突 | 裁定 | 关联 |
|---|---|---|
| “目标架构是多站点” vs “当前单站点事实” | 设计分三层（事实/目标/路径），UI 不做切换器 | ADR-01 |
| “实时平台” vs “轮询实现” | 明确当前为轮询；WS 列为独立后端阶段 | ADR-02 |
| “页面权限” vs “无认证” | 页面只读是产品约束；权限需后端 RBAC | ADR-03 |
| “无 CORS 看似安全” vs “真实风险” | CORS 不是安全措施；不得作为缓解依据 | ADR-03 |
| “Agent 有 owner 授权” vs “平台无授权” | 两平面隔离；不得类推 | ADR-03 |
| “08.4 已落地 UI” vs “仍缺后端能力” | 状态标注 EXISTING/PARTIAL/NOT SUPPORTED，不夸大 | 08.2 主文档 |
| “压测数据不足” vs “容量结论” | 只承认低负载实测（≈18–19 ev/s），容量需压测 | ADR-02 |

## 5. 部署边界冻结审查

| 边界 | 现状 | 建议 | 理由 |
|---|---|---|---|
| `/platform/` 与 `/app/` 同源静态托管 | 已实现（可选挂载） | **冻结**：保持两个独立入口 | Console 权限上下文与高频渲染需要独立文档 |
| `/platform` 与 `/app` 是否合并为单入口 | 未合并 | **冻结为不合并** | 合并会引入 iframe/权限/重渲染风险 |
| Site Server 与 Agent 本地 API | 分离 | **冻结**：禁止平台代理 Agent 命令 | 凭证与最小权限 |
| 平台数据平面与设备平面 | 隔离 | **冻结**：禁止跨平面注入 | 数据完整性与性能 |

> 冻结含义：本阶段及后续 UI 阶段不得改变上述边界；如需变更，必须另立 ADR 并人工审批。

## 6. 对 08.3 的输入与门禁

**允许进入 08.3 的内容**

- 只读页面的视觉系统、排版、表格、空态/错误态/未实现态规范。
- 状态徽标、时间字段呈现（三个时间语义分开）。
- 1920×1080 布局规范（需在 08.3 内做真实浏览器验收，见 F-16）。

**禁止进入 08.3 的内容**

- 登录/角色/权限 UI（无认证模型）。
- Site 切换器、多站点 Mock。
- 写操作入口。
- 实时推送/订阅 UI。
- 任何“实时”动效暗示（除非明确是轮询刷新）。

**门禁结论**

> 08.3 可以开始；但 08.3 的产出**不得**包含上述禁止项。生产部署/多站点/写能力/公网暴露必须先完成 08.2.2 安全评审。
