## 3. 新增决策登记

### D-08.2.3-01 — “40+ 频点”的语义

| 项 | 内容 |
|---|---|
| 决策 | 区分 **频道目录（Catalog）** 与 **并发频点（Concurrent）**：目录可为 40+（建议 48），节点并发仍为固件上限 8 |
| 理由 | `PROFILE_MAX_CHANNELS=8` 为代码事实；不能把目录条目数当作并发能力 |
| 备选 | A. 把频谱 256 bins 当作“40+ 频点”（不改固件，但不是频道语义）<br>B. 固件实现频道轮转覆盖目录（需固件变更）<br>C. 降低需求到 ≤8 |
| 影响 | PRD-RF-002、UI 热力图列数、容量模型 |
| 依赖 | SP-RF-01（固件） |
| 状态 | **PROPOSED** |

### D-08.2.3-02 — LAN 节点发现策略

| 项 | 内容 |
|---|---|
| 决策 | 首版以 **手动登记 + 桥接目录** 为主；mDNS/SSDP 自动发现列入后续 |
| 理由 | 现有 relay 无发现广播；Agent 仅 USB 发现 |
| 影响 | PRD-NET-002/003、Node Management |
| 依赖 | SP-RF-02 |
| 状态 | **PROPOSED** |

### D-08.2.3-03 — AP Direct 的定位

| 项 | 内容 |
|---|---|
| 决策 | AP Direct 仅作为**单节点本地接入**；不与 Site Server 自动同步；入库需经 Gateway 或后续离线导入 |
| 理由 | 节点无服务端、无 SoftAP；单网卡无法多 AP |
| 影响 | PRD-NET-008/009/010、UI 文案 |
| 依赖 | SP-RF-01（固件） |
| 状态 | **PROPOSED** |

### D-08.2.3-04 — 多 AP 汇聚禁止单网卡方案

| 项 | 内容 |
|---|---|
| 决策 | V1 不支持“单张普通 Wi-Fi 网卡同时连接多个节点 AP”；只允许 C1 多射频、C3 节点改 STA、C4 有线回传之一 |
| 理由 | 物理与驱动限制 |
| 影响 | PRD-NET-011、Gateway 硬件选型 |
| 依赖 | 硬件采购决策 |
| 状态 | **PROPOSED** |

### D-08.2.3-05 — RF 事实表与原始帧并存

| 项 | 内容 |
|---|---|
| 决策 | 新增 `rf_measurements` 等 Channel 级事实表；`measurements` 原始帧保留，不改写 |
| 理由 | 现有表无法按频道/频率/质量查询 |
| 影响 | DM 全篇、架构变更审批 |
| 依赖 | 人工批准 schema + Alembic |
| 状态 | **PROPOSED** |

### D-08.2.3-06 — dBFS 与 dBm 分离

| 项 | 内容 |
|---|---|
| 决策 | 原始 `rssi_dbfs` 必存；`rssi_dbm` 仅在存在校准档案时填写，否则 `NULL` 且 `quality='uncalibrated'`；跨节点比较需显示校准状态 |
| 理由 | 固件输出 dBFS；不同节点增益/天线不同 |
| 影响 | PRD-RF-009、图表 Y 轴、热力图色标 |
| 依赖 | SP-RF-08 |
| 状态 | **PROPOSED** |

### D-08.2.3-07 — RF 读路径首版采用短轮询

| 项 | 内容 |
|---|---|
| 决策 | 首版 1–2 s 轮询；不依赖新增前端 WebSocket；WS 作为后续优化 |
| 理由 | 事件流 ADR 仍 `PROPOSED`；SP-12 未实施 |
| 影响 | IA §8、容量模型 |
| 依赖 | ADR-08.2.1-02 补充 |
| 状态 | **PROPOSED** |

### D-08.2.3-08 — 图表系列上限

| 项 | 内容 |
|---|---|
| 决策 | 每图最多 8 节点、8 频道；系列硬上限 64，建议 ≤32；超限提示而非静默截断 |
| 理由 | 可读性与渲染性能；与 `--s1..--s8` 对齐 |
| 影响 | IA §4/5/6、API §1.3 |
| 依赖 | Phase 08.3 补充 |
| 状态 | **PROPOSED** |

### D-08.2.3-09 — 写入前聚合与分层保留

| 项 | 内容 |
|---|---|
| 决策 | 频道 1 Hz、频谱 0.2 Hz 写入；1 s/1 m/1 h 分层；原始逐帧不长期保留 |
| 理由 | 8 节点逐帧 ≈3,944 行/s，SQLite 不可持续 |
| 影响 | 容量文档、SP-RF-05 |
| 依赖 | 人工批准保留策略 |
| 状态 | **PROPOSED** |

### D-08.2.3-10 — 身份层级命名

| 项 | 内容 |
|---|---|
| 决策 | 固定四级：`site_id` / `gateway_id`（=Agent）/ `node_id`（=Device）/ `node_boot_id`；文档与 API 统一，不再混用 `agent_id/device_id` 作为对外主名 |
| 理由 | 现库字段名与产品语义错位 |
| 影响 | API §1、DM §4 |
| 依赖 | 文档级即生效（命名约定），字段重命名不做 |
| 状态 | **PROPOSED** |

### D-08.2.3-11 — RF Workbench 与 Console 边界

| 项 | 内容 |
|---|---|
| 决策 | RF Workbench 新建 4 页；`/app/` 保持独立；不内嵌、不复制其交互；平台页不复用 Console 的单设备全局状态 |
| 理由 | 避免破坏 Console 操作效率与设备连接 |
| 影响 | IA §1/§9 |
| 依赖 | Phase 08.3 |
| 状态 | **PROPOSED** |

### D-08.2.3-12 — 接入能力不新增协议字段

| 项 | 内容 |
|---|---|
| 决策 | 不修改冻结二进制协议；LAN/AP 能力通过固件内部实现、中继封装、Agent/Server 侧模型解决 |
| 理由 | 项目硬约束 |
| 影响 | ARCH 全篇、SP-RF-01 |
| 依赖 | 无（约束性决策） |
| 状态 | **PROPOSED** |
