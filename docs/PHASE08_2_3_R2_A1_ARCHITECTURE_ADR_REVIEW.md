## 3. A1-02 — `ADR-08.2.1-02` 事件流裁定

### 3.1 结构化审阅

| 项 | 内容 |

| 备选方案 | `§3.3` 配额调度（按比例/时间片/最大等待）；`§3.4` 持久化缓冲 A（Agent 本地 WAL/Spool）/ B（Measurement 落盘）/ C（不持久化）；`§3.5` 逐事件 ACK vs 批量 ACK；`§4` 新增 `/ws/v1/site` vs 继续轮询。 |

| 数据影响 | 若采纳持久化缓冲，需要新增 WAL/Spool 存储；`(site_id,event_id)` 唯一键继续作为幂等基础。 |
| API 影响 | 不新增 `/ws/v1/site`；未来可能新增 `ingest.ack` 消息类型（需单独评审，不得改现有字段）。 |

| 安全影响 | 未来 WS 必须首条认证、Site Scope 校验、越权关闭（4403）。 |
| 兼容影响 | 协议冻结；任何新增消息类型都必须单独批准；旧 Agent 不受影响。 |
| 不批准的后果 | RF 图表无法确定轮询/推送策略；实时能力无法立项；队列饥饿与容量风险无裁定依据。 |
| 需要补充的内容 | **补充 1**：RF 读路径首版为只读轮询 1–2 s，不依赖新增前端 WS（对应 D-08.2.3-07）。<br>**补充 2**：配额参数与容量结论必须由后续压测得出，当前 `≈18–19 事件/s` 只能证明低负载余量。 |
