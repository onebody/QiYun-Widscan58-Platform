## 1. A3 — 40+ 频点语义

| 项 | 内容 |
|---|---|
| 决策编号 | `A3` |
| 当前状态 | `PROPOSED` |
| 原始证据 | `RF_PRODUCT_REQUIREMENTS.md` PRD-RF-002；`repo/firmware/src/scan/profile.h` `#define PROFILE_MAX_CHANNELS 8`；`DECISION_REGISTER.md` `D-08.2.3-01`；`RF_DATA_MODEL.md` `§5.1`（`rotationHz`/`hopsTotal`）；`HUMAN_APPROVAL_REGISTER.md` `§4` |
| 决策背景 | “每节点 40+ 频点”存在语义歧义：目录条目数、轮转覆盖、并发接收、连续 FFT 是四种不同能力。固件实际上限 8 个频道，若把目录数当作并发数对外宣称，会形成虚假能力。 |
| 选项 | A 接受“目录 ≥40 + 并发 ≤8 + 轮转覆盖”的语义；B 降低需求到 ≤8；C 要求固件实现 40+ 并发（需固件变更，违反协议冻结前提） |
| 推荐意见 | **批准 A（仅需求语义层）**；硬件能力声明保持 `NOT VERIFIED`，直至 A8 固件审计给出结论 |
| 批准后影响 | PRD-RF-002 可保留“目录 ≥40”；UI 选择器/热力图按目录展示、按并发高亮；容量模型按 ≤8 并发计算；不得宣称 40+ 并发 |
| 拒绝后影响 | 无法定义验收口径；容易把目录数当并发能力对外宣称；UI 与容量模型缺基准 |
| 需要满足的前置条件 | A8 固件审计确认轮转是否存在、单频道刷新周期、切换开销、40+ 覆盖所需时间；`rotationHz` 可用 |
| 人工审批结果 | （空） |
| 审批日期 | （空） |
| 审批备注 | （空） |

### 1.1 四类能力必须分开表述

| 能力 | 含义 | 当前事实 | 状态 |
|---|---|---|---|
| 频点目录覆盖 | 系统知道多少个逻辑频点（A/B/E/F/R/L 等） | 可设计 ≥40（建议 48），属产品/数据层 | 可批准（语义） |
| 扫描轮转能力 | 节点按计划在 8 个频道间轮转，遍历目录需要多轮 | 固件有 `rotationHz`/`hopsTotal` 概念，**未实测** | `NOT VERIFIED` |
| 并发接收能力 | 同一时刻同时观测的频道数 | `PROFILE_MAX_CHANNELS=8`（`profile.h` 第 8 行） | VERIFIED（上限 8） |
| 连续 FFT 能力 | 连续频谱采样（非离散频点轮转） | 无证据；现有为离散频道扫描 | `NOT VERIFIED`；**不得插值伪造** |

**结论**：“40+”只能作为**目录覆盖目标**，不能作为并发或连续 FFT 能力。

### 4.1 必须补齐的 7 项

| # | 项目 | 当前材料 | 缺口 | 补齐要求 |
|---|---|---|---|---|
| 1 | `rssi_dbfs` 原始测量值 | `RF_DATA_MODEL §3.4` 已定义必存，来源 `payload.channels[].rssi` | 无 | 明确必填、单位 dBFS、不得换算覆盖 |

- 迁移执行：**必须另行人工批准**，本轮不执行。
