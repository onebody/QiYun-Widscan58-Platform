5. “推荐意见”是审阅建议，不是批准；不得据以执行任何实施动作。
6. 任何批准仅代表“决策层面同意”，**实施仍需另行取得实施批准**（见 §7）。

## 3. 审批规则

| 允许填写的结果 | 含义 |
|---|---|
| `APPROVED` | 批准该决策项（可附条件） |
| `REJECTED` | 拒绝该决策项 |
| `REVISION REQUIRED` | 退回修改，补齐后重新提交 |
| `DEFERRED` | 暂缓，等待外部依据（如实测数据） |
| `NOT VERIFIED` | 证据不足，不能批准也不能拒绝 |
| `A` / `B` | 仅用于 A9 的两个正式选项 |

**填写要求：**

- 每项必须有“审批结果 + 审批日期 + 审批备注（含条件）”；缺任一项视为未完成。
- 附条件批准必须在备注中列明条件；条件未满足前，对应门禁不得转 `PASS`。
- 不得批量填写“全部 APPROVED”；必须逐项。
- 不得把 A1/A2 的批准等同于实施批准。

## 7. 批准后仍需单独批准的动作

即使本文件全部填写 `APPROVED`，下列动作**仍不得自动执行**：

1. 修改任何产品代码（含 Site Server、Gateway Agent、前端）。
2. 新增/修改数据库表、执行任何数据库迁移。
3. 修改固件、设备协议、REST API、WebSocket 协议。
4. 修改运行配置或部署配置。
5. 启动 SP-00–SP-17 的任何实现工作包。
6. 启动 Phase 08.2.4 实际审计执行（含硬件验证）。
7. 启动 Phase 08.3 或任何后续开发阶段。
8. 采购任何硬件（A5 仅批准评估）。

**原则：决策批准 ≠ 实施批准。**
