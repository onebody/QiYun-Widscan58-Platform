## 1. 产品定位

QiYun / widscan58 是面向 FPV 赛事与射频现场的 **多节点频段监测平台**：

1. 每个 RF 节点独立扫描 5.8 GHz 频段，输出各频点 RSSI 与频谱。
2. 多节点结果按 `Node × Channel × Time` 保留，**不跨节点合并同一频点的 RSSI**。
3. 提供三类分析视图：频点扫描频谱图、RSSI 实时趋势图、节点 × 频点热力图。
4. 节点支持两种接入形态：已有 Wi-Fi 局域网（LAN）与节点自身 SoftAP（AP Direct）。
5. 平台侧保留现有 Overview / Sites / Gateways / Devices / Measurements / System 页面；
   原始 RF Console `/app/` 继续独立存在。

**明确不在本阶段范围**：不改固件、不改冻结的二进制设备协议、不改 `/app/`、不启动 Phase 08.3。

## 2. 用户场景

| 编号 | 场景 | 参与者 | 目标 |
|---|---|---|---|
| SC-01 | 场馆已有 Wi-Fi，节点上电后自动出现在平台 | 现场工程师 | 免手动配置完成接入 |

| SC-05 | 单节点多频点趋势 | RF 分析师 | 观察干扰随时间的迁移 |
| SC-06 | 历史回溯 | RF 分析师 | 按时间窗口查询节点 × 频点结果 |
| SC-07 | 节点掉线/重启 | 运维人员 | 明确区分“无数据 / 过期 / 节点重启” |

## 4. 需求清单

优先级：`P0` 首版必须；`P1` 首版应具备；`P2` 后续版本。
范围：`V1` 首版；`V1+` 后续。

### 4.1 节点管理（NODE）

| 编号 | 需求 | 优先级 | 范围 | 现状 | 验收标准 |
|---|---|---|---|---|---|
| PRD-NODE-001 | 节点注册后进入平台节点列表，显示节点 ID、名称、硬件型号、固件版本、接入方式、在线状态 | P0 | V1 | `PARTIAL`：Device 表与 Devices 页面已有，但无“接入方式”字段 | 列表中每节点唯一一行；字段为空显示 `—`；不伪造 |
| PRD-NODE-002 | 节点身份必须稳定且可区分同一硬件与不同硬件 | P0 | V1 | `PARTIAL`：`device_id` 由 Agent 合成，`INFO` 可带 MAC | 重启前后同一硬件 ID 不变；低置信 ID 显式标注 |
| PRD-NODE-003 | 节点连接管理：连接、断开、重连、状态查看 | P0 | V1 | `PARTIAL`：Agent 有设备状态机；平台无写入口 | 状态变化有事件；断连不隐藏节点 |
| PRD-NODE-004 | 节点能力查询：频点范围、最大并发频点数、是否有频谱、扫描周期 | P0 | V1 | `GAP`：无能力模型与接口 | 能力来自节点上报或目录，不由前端猜测 |

### 4.2 Wi-Fi LAN 接入（NET-LAN）

| 编号 | 需求 | 优先级 | 范围 | 现状 | 验收标准 |
|---|---|---|---|---|---|
| PRD-NET-001 | 节点接入已有 Wi-Fi 局域网（STA），并向平台/网关建立数据通道 | P0 | V1 | `PARTIAL`（验证见审计文档 Q1）：仅 ESP32-S3 relay 镜像具备 | 节点上电后进入 LAN 并建立通道；失败可诊断 |
| PRD-NET-002 | 平台自动发现 LAN 内节点 | P0 | V1 | `GAP`：无 mDNS/SSDP/扫描；仅桥接服务的内存节点列表 | 无需手输 IP 即可发现；发现结果可区分来源 |
| PRD-NET-003 | 支持手动输入节点 IP/主机名接入 | P0 | V1 | `GAP`：Agent 仅 USB 发现；平台无入口 | 手动条目可保存、可编辑、可删除 |
| PRD-NET-004 | 节点连接状态管理（连接中/已连接/认证中/重连/失败/禁用） | P0 | V1 | `PARTIAL`：Agent 设备状态机有 9 态；LAN 语义未映射 | 状态互斥且可解释；不得把“有 IP”显示为“在线” |
| PRD-NET-005 | 节点接入认证：节点凭证不得出现在 URL 查询参数或明文日志 | P0 | V1 | `GAP`（relay 现为无凭证 WS） | 凭证仅头部或首条消息；日志无明文 |
| PRD-NET-006 | 节点心跳与断线重连（有上限、有退避） | P0 | V1 | `PARTIAL`：relay 有 500 ms–30 s 退避；Agent 有设备重连 | 断线后自动恢复；认证失败停止重试并明确报错 |
| PRD-NET-007 | 节点数据通道与 USB/串口能力并行共存，不互相阻塞 | P1 | V1 | `UNKNOWN`：无实测证据 | USB 与 LAN 节点同时在线；任一通道故障不拖垮其他通道 |

### 4.4 多节点、多频点测量（RF）

| 编号 | 需求 | 优先级 | 范围 | 现状 | 验收标准 |
|---|---|---|---|---|---|
| PRD-RF-001 | 每个节点独立产生并保留测量结果，包含节点标识 | P0 | V1 | `PARTIAL`：`Measurement` 有 `device_id`，但数据在 `payload_json` 内 | 查询任一结果可还原 node_id |
| PRD-RF-002 | 支持 40+ 个可探测频点的频点目录 | P0 | V1+ | `GAP`：固件 `PROFILE_MAX_CHANNELS=8`，默认 R1–R8 | 目录 ≥40 条且带频率；节点可覆盖目录（需固件支持） |
| PRD-RF-003 | 统一数据维度 `Node × Channel × Time` | P0 | V1 | `GAP`：无 channel 级事实表 | 任意查询可按三维切片 |
| PRD-RF-004 | 不得把同一频点多个节点 RSSI 合并为单一值 | P0 | V1 | `PROPOSED` | 接口与存储均按节点分行；聚合算法不跨节点 |
| PRD-RF-005 | 最多 8 个频点同时参与对比 | P0 | V1 | `PROPOSED` | 超过 8 个频点时明确拒绝或提示，不静默截断 |
| PRD-RF-006 | 测量携带采样时间与扫描周期信息 | P0 | V1 | `PARTIAL`：帧有 `tMs/seq`，`TELEMETRY` 有 `rotationHz`，API 未暴露 | 结果含设备时间、Agent 接收时间、站点接收时间 |
| PRD-RF-007 | 数据质量语义：缺失、过期、重复、重启、频点映射变更、未校准 | P0 | V1 | `GAP` | 缺失为 `null` 而非 0；过期有阈值与标记 |
| PRD-RF-008 | 历史查询支持时间窗口与节点/频点过滤 | P0 | V1 | `GAP`：现接口仅按 device 分页、无时间过滤 | 时间窗口生效；分页稳定 |
| PRD-RF-009 | RSSI 校准：不同节点的 RSSI 不天然可比，需显式校准状态 | P0 | V1 | `GAP`：帧单位为 dBFS，dBm 需 Web 侧校准曲线 | 未校准数据显示 `uncalibrated`，不伪造 dBm |

## 5. 首版与后续范围

### 5.1 首版（V1）建议范围

1. 节点管理页面（只读 + 连接状态），复用 Device 表与 Agent 状态。
2. Wi-Fi LAN 接入：复用 ESP32-S3 relay 镜像，补齐发现与手动 IP（需固件/桥接改造，另批）。
3. 8 频点以内的独立测量与三类视图（频点来自现有 `CHANNELS` 计划）。
4. `Node × Channel × Time` 存储模型与 RF 查询 API（新增表，需迁移）。
5. 历史查询（按时间窗口）与缺失/过期语义。

### 5.2 后续范围（V1+）

1. 40+ 频点目录与节点覆盖：依赖固件频点扫描调度（冻结协议之外的固件变更）。
2. 单节点 SoftAP 与 AP Direct 数据接口：依赖固件启用 SoftAP 与节点侧服务端。
3. 多 AP Gateway 汇聚（多射频/多网卡）。
4. 真实 dBm 校准与跨节点可比性认证。
5. WebSocket 实时推送（替代高频轮询）。

### 5.3 明确不做（本阶段及 V1 不承诺）

- 多节点频谱融合算法、RF 定位、AI 自动分析。
- OTA 固件升级。
- 修改冻结二进制协议、C5 PHY/DSP。
- 用 Mock 数据冒充真实节点数据。
