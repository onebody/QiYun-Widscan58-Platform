## 1. 立项背景

Phase 08.2.3 审计确认：

| 事实 | 证据等级 | 证据 |
|---|---|---|
| 固件频道上限 8 | VERIFIED | `repo/firmware/src/scan/profile.h` `PROFILE_MAX_CHANNELS=8` |
| SoftAP 未编译 | VERIFIED | `sdkconfig.defaults`、`sdkconfig.esp32s3-relay` |
| 节点无本地服务端 | VERIFIED | `src/` 无 HTTP/WS server |
| Wi-Fi LAN 仅 S3 relay 具备 | VERIFIED | `src/net/ws_link.c`、条件编译 |
| RSSI 原始为 dBFS | VERIFIED | `frame_parser.py` |
| 时间戳为单调 ms | VERIFIED | 帧头 `tMs`/`seq` |
| 40+ 并发、同芯片 Wi-Fi 并行、资源余量 | NOT VERIFIED | 无实测 |

产品目标（40+ 逻辑频点、AP Direct、多节点 LAN）与固件现状存在结构性差距。因此建议将固件能力评估独立立项，先审计、后决策，**不直接进入开发**。

---

## 2. 审计目标

1. 用实测回答“当前固件到底能做什么”，不依据其他 QiYun 项目或芯片手册推断。
2. 量化 40+ 频点的覆盖方式、周期与代价。
3. 验证 SoftAP、节点服务端、LAN 接入的可行性边界。
4. 测量扫描与 Wi-Fi 并行的真实影响。
5. 测量 RSSI 精度、校准可能性与时间戳可靠性。
6. 测量 RAM / Flash / CPU / 功耗 / 热稳定性。
7. 给出“可做 / 不可做 / 需硬件变更”的结论与前置条件。

## 4. 非目标

- 不在本审计中实现 40+ 并发、SoftAP 产品化或节点服务端产品化。
- 不修改冻结二进制协议。
- 不修改 `/app/`、`/platform/`、Site Server、Agent。
- 不做 RF 定位、频谱融合、AI 分析。
- 不采购量产硬件（仅申请测试样机）。

## 8. 测试记录格式

每条用例必须输出如下 JSON（示例结构，不含伪造数值）：

```json
{
  "case_id": "F-05",
  "firmware": { "version": "", "build_id": "", "commit": "" },
  "hardware": { "board": "", "mac": "", "antenna": "" },
  "environment": { "temperature_c": null, "supply_v": null },
  "setup": { "signal_source_dbm": null, "attenuation_db": null, "distance_m": null },
  "measurements": [],
  "result": "NOT_VERIFIED",
  "evidence": ["path/to/log", "path/to/screenshot"],
  "notes": ""
}
```

规则：

- 未测量字段填 `null`，不得填估算值。
- `result` 只能是 `PASS/FAIL/NOT_VERIFIED/BLOCKED`。
- 每条都必须有可复现步骤与原始日志。
